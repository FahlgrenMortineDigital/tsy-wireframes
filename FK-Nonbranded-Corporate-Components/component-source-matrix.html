Key insights

What the three-way comparison reveals.

1. The doc's list is incomplete, not the wireframe

Several components flagged earlier as "invented" are real — Continue Link Block, Back to Top, Topic Highlight, Carousel Indicator, Anchor Navigation and Person Card all exist in Figma. The doc simply omits them because live they're implemented as Container/Text style presets (e.g. cmp-container-link-block, cmp-text__contact-card) rather than discrete components.

2. Six "Figma-only" components are confirmed live

Continue Link Block, Back to Top (site-wide), Topic Highlight / Highlight Carousel, Carousel Indicator, Teaser Info, and Social Media Icons all render on the production site — validating the wireframe entries that carry them.

3. Real wireframe gaps (in doc AND Figma AND/or live, but missing from wireframe)

Language Navigation (used heavily live), Category List (powers the news/listing pages live), Teaser Info (Figma + live), and Story Scroll (doc + Figma) are the strongest add candidates. Suggest Location and Login are FK-only and in scope if needed.

4. One live-only surprise: FAQ

cmp-faq appears on every sampled page but is in neither the doc's component list nor the Figma library as a named component. Worth confirming with the dev team whether it's a distinct component or an Accordion variant.

5. Doc-only components can't be wireframed from design

Embed, Content/Experience Fragment, Tags Viewer, Interactive Media, Smart Crop, Progress Bar, SCORM, Recipe, BMI/Dosing have no Figma artifact — they're AEM authoring/runtime constructs. Flag them as "AEM-only" rather than treating them as drawing gaps.

6. Naming should be reconciled to the AEM/Figma canon

Stage → Stage Hero · Topic Highlight/Story Row → Image Text Block · Counter/Stat Strip → Facts and Figures · Asset Card → Download · Topic Area → Quick Link Cards / List · Section Heading → Title.
